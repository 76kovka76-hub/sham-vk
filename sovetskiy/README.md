# SOVETSKIY — мемы на кадрах советского кино

Группа: **https://vk.ru/club243244760**. Новый проект не использует SHAM или SKRBL для публикации и ничего не меняет в их контенте.

## Главное правило: кадр и шутка обязаны совпадать по смыслу

Не используем случайную фотографию из фильма только потому, что на ней знакомый герой или «подходящее настроение». **Сначала смотрим конкретный кадр**, затем выбираем оригинальную короткую шутку, которую он действительно усиливает:

- **Один кадр**: выражение лица, действие, жест и видимые предметы должны объяснять шутку без длинного дополнительного текста; надпись создаёт смешной контраст с реальной сценой.
- **Коллаж из двух кадров**: есть ясное «до/после» или «ожидание/реальность», а порядок кадров соответствует сюжету.
- Проверяем, что подпись ничего не приписывает изображению вопреки видимому действию. Остроумный статус должен быть привязан к конкретной сцене, а не случайному портрету.
- В `scene_matches.json` для **каждой** пары записываются настоящие наблюдения по каждому кадру, ссылка на просмотренный кадр, объяснение соответствия шутке и результат редакторской проверки.
- В `scene_quality.py` установлен жёсткий запрет: **ни одна пара со статусом `pending` не проходит в отложенную очередь**, даже если на Wikimedia Commons подтверждён статус public domain.
- Все 14 ранее предложенных сочетаний помечены `pending`. Это **кандидаты**, а не доказанно смешные или совпадающие по смыслу кадры. Одного названия эмоции из каталога недостаточно.
- Генератор сохраняет PNG-предпросмотр с `scene_match_approved=false`, чтобы проверить реальную композицию. Успешный рендер не означает разрешение на публикацию.
- Если не нашлось подходящего кадра с понятным выражением/действием, **пропускаем** публикацию вместо случайной картинки.

Права на кадр и смысловое соответствие — две **отдельные обязательные** проверки.

## Схема

- Короткая злободневная **собственная** шутка или статус из `jokes.py`, обычно одна-две строки.
- Оригинальный **кадр советского фильма** из `sources.json`: реальные изображения, не стилизация AI и не текстовый пост без картинки.
- Два макета в `render.py`: **один кадр** с крупной подписью и **коллаж из двух кадров** с контрастной реакцией.
- Визуальный стиль: красные плакатные элементы, винтажная бумага, перфорация киноленты, контрастный русский текст, формат 1200 × 1200.
- В описании — ясный самостоятельный короткий пост, название фильма и **3 хэштега**.
- `publisher.py` помещает сообщение с настоящим PNG в отложенную очередь VediSMM строго для VK ID **243244760**. Дедупликация проверяет шутки, исходные кадры и слоты расписания.
- `.github/workflows/sovetskiy.yml` запускается в GitHub, работает при выключенном домашнем компьютере и использует существующий секрет `VEDISMM_TOKEN`. Он **не требует платных API**.

## Права на кадры

Советские фильмы **не становятся автоматически общественным достоянием только из-за возраста**. У конкретного файла на Wikimedia Commons должна быть подтверждена правовая маркировка `Public domain` / `CC0` **и** ручная запись в `sources.json`. Перед каждой публикацией `commons.py` перепроверяет её через MediaWiki API. Если статус прав не подтверждён или скачивание недоступно, публикация **пропускается**, а не подменяется кадром из интернета с неизвестными правами.

Начальный тестовый набор — 7 отдельных источников из ранних советских фильмов «Аэлита» (1924) и «Броненосец „Потёмкин“» (1925). Для кадров из более поздних советских фильмов и мультфильмов нужна отдельная проверка прав, разрешение правообладателя либо подходящая лицензия.

## Надёжность источников

Wikimedia Commons иногда ограничивает скачивание (HTTP 429). Бот теперь использует более лёгкие thumbnail-файлы, соблюдает Retry-After и не делает сетевые обходы. При недоступном источнике публикация не совершается, а уже вышедшие посты не затрагиваются.

## Запуск

1. GitHub Actions → **SOVETSKIY — советское кино, короткие мемы** → `Run workflow` → `preview` — скачать реальный PNG и проверить шутку.
2. Действующее подключение VK ID 243244760 к ВедиSMM проверяется read-only задачей `SOVETSKIY — проверка подключения ВК`.
3. После проверки изменить `sovetskiy/settings.json`: `autopublish: true`. Затем workflow `enqueue` или пуш с маркером `[START_SOVETSKIY]` поставит один пост в ВедиSMM.
4. В пилотном режиме расписание: **4 публикации в сутки** в 00:00, 06:00, 12:00 и 18:00 UTC, отложенная очередь на ~18 часов вперёд. GitHub cron может запускаться с задержками.
5. Бот автоматически прекращает генерацию, когда заканчиваются **уникальные, проверенные по правам** изображения. Первого набора кадров не хватит на долгосрочные 4 публикации в день; его необходимо регулярно и законно расширять.

**Текущий статус:** подготовка и предпросмотр; до успешной визуальной проверки `autopublish=false`. Важно: зелёный workflow без запланированного поста не означает, что ВК опубликовал картинку.
