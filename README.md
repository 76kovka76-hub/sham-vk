# SHAM — автономный бесплатный мем-бот ВКонтакте

**ВК:** https://vk.ru/club243230846 (ID `243230846`)  
**GitHub:** https://github.com/76kovka76-hub/sham-vk

> Версия без платного OpenAI API и без постоянно включённого компьютера. GitHub Actions **пополняет очередь каждые 5 минут**, стремясь поддерживать до 12 часов запланированных постов; цель — 96 публикаций в сутки. **31 сменяемый визуальный жанр, без доминирования аниме**. Фактическое число успешных публикаций зависит от доступности бесплатной волонтёрской сети AI Horde и VK/ВедиSMM.

## Редакторский конвейер SHAM v3 (13 ноября 2026)

- **Пять живых идей:** `live_jokes.py` обращается к бесплатной анонимной текстовой модели OVH, запрашивает пять сюжетно разных авторских шуток и локально выбирает наиболее свежий вариант. Этот путь включён в GitHub Actions через `SHAM_LIVE_TEXT=true`. Если модель недоступна, неправильно отвечает или шутки проваливают проверки — используется согласованный локальный банк. Важно: безлимитное производство оригинальных шуток **не гарантируется** бесплатным сервисом.
- **Жёсткий и абсурдный юмор:** `hard_jokes.py` и `fresh_jokes.py` добавляют 48 самостоятельных историй, помимо 18 ранних коротких шуток и 30 тематических банков. Не смешиваем несвязанные завязки и концовки.
- **Новые смысловые фильтры:** `meaning_guard.py` блокирует смысловые дубликаты даже при подмене слов, например «зарплата сбежала» и «зарплата исчезла», и близкие парафразы последних записей. Это эвристическая проверка, а не гарантия семантического равенства для всех возможных фраз.
- **Точная сцена:** для каждой цельной истории задаётся собственное англоязычное физическое действие. `image_guard.py` требует точного визуального задания и не допускает пустые и почти одинаковые картинки.
- **Визуальный контроль:** `vision_review.py` в режиме `best_effort` пытается отправить **готовое изображение** и текст шутки в мультимодальную модель OVH для независимой проверки. Уверенное несоответствие блокирует публикацию. Если анонимная модель недоступна или превышен её лимит, проверка помечается `unavailable`; изображение всё ещё может быть поставлено в очередь после остальных проверок. Полную гарантию совпадения этот режим не даёт. Более строгий `SHAM_VISION_CHECK=strict` отменяет публикацию и при недоступной проверке.
- **Шесть оформлений надписей:** `meme_layout.py` чередует градиент, редакционную плашку, тёмную рамку, киношные полосы, неон и бумажный коллаж; надписи остаются точно набранными кириллицей.
- **Новые истории впереди старого банка:** редактор выбирает самостоятельные жёсткие и абсурдные сюжеты с собственными визуальными сценами, а тематические сочетания использует только при исчерпании цельных шуток.
- **Читаемый русский текст:** надписи рисуются Pillow после нейрогенерации, а не самой моделью. Если текст нельзя вписать достаточно крупно без выхода за рамки, генерация прекращается, вместо публикации мелких нечитаемых букв.
- **История и очередь:** новые записи получают `quality_version=3`; ранее опубликованные посты не удаляются. Старые отложенные посты **не удаляются автоматически**: сначала сохраняем бесперебойность расписания. Снятие запланированного аниме до подготовки успешной замены могло привести к пропуску публикации при сбое бесплатного генератора. Новый контент занимает следующие свободные слоты. Никаких новых паролей, TinyFish или отдельного сервера не требуется.

## SHAM v4 — рост качества и вовлечённости (13 ноября 2026)

- **Новые редакторские эксперименты:** `editorial_experiments.py` меняет направление юмора и ставит редакторскую оценку. Сильный мат сам по себе не даёт высокого рейтинга.
- **Комьюнити-идеи:** `community_signals.py` считывает только публичные комментарии на подтверждённых постах VK. Сохраняет лишь агрегированные общие темы (не имена, не ID людей, не тексты комментариев); темы используются для вдохновения новых оригинальных шуток. Если VK API отказывает, функция не мешает публикации.
- **Прозрачность доступов:** подключение ВедиSMM публикует мемы, но токены ВК на момент проверки возвращают ошибки `5`/`27` для чтения стены и комментариев. При отсутствии настоящих метрик SHAM не подменяет их числами и не публикует фальшивый недельный топ.
- **Реальная аналитика:** `sham_insights.py` читает метрики официального VediSMM API, при их отсутствии пытается получить реальные лайки, репосты и просмотры VK только по опубликованным SHAM постам. Демонстрационные и отсутствующие метрики не засчитываются. Отчёты выпускаются отдельной GitHub Actions workflow `sham-insights.yml`.
- **Топ недели:** в воскресенье `sham_weekly_top.py` может опубликовать новый постер с тремя лучшими мемами и ссылками на них — только если есть минимум три поста с настоящими подтверждёнными метриками. Иначе не публикует выдуманный рейтинг.
- **GIF и видео:** `sham_motion.py` готовит анимированную GIF-версию и MP4 с проявляющейся концовкой. Это безопасный **предпросмотр** через GitHub Actions → SHAM → `media-preview` (или тест-коммит `[MEDIA_PREVIEW]`). MP4 формируется через переносимый FFmpeg, устанавливаемый только в ручном тестовом режиме. Самостоятельная отправка GIF/MP4 в VK пока отключена до проверки совместимости ВедиSMM с конкретным медиаформатом.
- **Публикация PNG остаётся прежней:** существующий планировщик VediSMM, защита от двойной отправки, семантические фильтры и контроль картинки работают независимо от новой аналитики и медиафункций.
- **Частота:** цель 96 слотов в сутки пока не меняем без реальной статистики. После появления достаточных показателей можно сравнить графики и корректировать их только на данных.

## Перезапуск качества SHAM — 13.11.2026

- **Приоритет юмора:** `editorial_jokes.py` — 44 заново написанные полноценные истории со сценами, а не случайными комбинациями фраз; в `SHAM_EDITORIAL_MODE=quality_first` запрещён возврат к банальным 600 комбинациям `TOPICS`. Дополнительные ранее отобранные сюжеты разрешены только по явному списку.
- **Публикуем реже, но лучше:** для *новых* слотов `SHAM_POST_INTERVAL_MINUTES=60` (целевой максимум 24/сутки вместо 96). Исторические отложенные публикации уже могут иметь более частый график и не меняются без отдельной редакторской проверки.
- **Недоступная текстовая нейросеть:** OVH регулярно отвечает таймаутом; теперь только 12% новых слотов делают бесплатную попытку, вместо бессмысленной задержки на каждом посте. Качество не заменяется парой случайных заготовок. При исчерпании проверенных шуток бот **пропускает слот**, а не публикует примитивную шутку.
- **Визуальный контроль:** реальные предпросмотры показывали расхождение изображения и шутки; старый мультимодальный запрос выдавал ошибку 422. `vision_review.py` обновлён под API chat/completions и модель Qwen3.8-27B. Негативный вывод модели с высокой уверенностью блокирует пост. Если бесплатная модель недоступна, `best_effort` честно сохраняет статус `unavailable`; автоматический гарантированный семантический контроль пока не доказан.
- **Слабая старая очередь:** `review_queue_once.py` маркирует конкретные прочитанные и отвергнутые отложенные шутки **только** при запасе не менее 90 минут. `queue_cleanup.py` повторно проверяет статус и ETag в ВедиSMM перед отменой. Опубликованные посты и ближайшие записи не отменяются; старые слоты не дублируются. Очистка не гарантирует немедленного заполнения снятых слотов.
- **Новые изображения:** приоритет точной физической сцены и действия; исключены стандартные заготовленные реакции на шутки с собственным сюжетом.

## Возможности

- Каждый успешный пост: авторская ситуация + смешной панчлайн на **генерируемом нейросетью** PNG 1080×1080 с текстом, короткая подпись и **ровно 3 хэштега**.
- Хэштеги выбираются по теме из словаря распространённых русскоязычных тегов. Внутри одного поста все 3 разные; тройка из предыдущих постов больше не используется. Одиночные теги не повторяются в последних 12 публикациях, когда это возможно. Бесконечного запаса *популярных* тегов нет: одиночные теги со временем будут возвращаться. Реальная текущая популярность тегов автоматически не проверяется.
- Редакторская библиотека v2: короткие заранее согласованные шутки по 30 микросюжетам. Независимое склеивание случайных завязок и панчлайнов запрещено.
- Защита от точных повторов текста в `state/history.json`; SHA-256 идентификатор каждой шутки. После публикации бот фиксирует идентификатор временного слота и ID поста ВК.
- `wall.post` передаёт стабильный `guid` для уменьшения риска двойной отправки.
- Мем публикуется **только с прикреплённым фото**. При неудачной загрузке картинки отправка текста отменяется.
- Без платного API — Python, Pillow, GitHub Actions, AI Horde и ВедиSMM. Бесплатный AI Horde не гарантирует скорость и количество запросов: во время загрузки сети публикации пропускаются. При исчерпании банка мемов бот завершит запуск с ошибкой; банк примерно на 3500 комбинаций.

## Альтернативный бесплатный канал: ВедиSMM (экспериментально)

Если VK_USER_TOKEN получить не удалось, можно использовать VediSMM: https://vedismm.ru/. На ноябрь 2026 сервис **заявляет** бесплатное использование без лимита публикаций и предоставляет официальный REST API для загрузки файлов, создания записей и запуска публикации. **Это не гарантия успешной отправки картинок в VK**: ВКонтакте по-прежнему ограничивает метод photos.getWallUploadServer для ключей сообществ. Проверить путь можно только после подключения SHAM.

**Единовременная настройка владельцем** (после неё ПК можно выключить):
1. Зарегистрироваться в ВедиSMM и подключить сообщество VK **243230846**. Ключ сообщества вводить только на сайте сервиса, не в чате.
2. В личном кабинете ВедиSMM создать **персональный API-токен (PAT)** с правами `accounts:read`, `media:write`, `posts:write`, `posts:publish`, `jobs:read`. Не путать с VK_USER_TOKEN.
3. В GitHub Actions Secrets добавить `VEDISMM_TOKEN` со значением PAT: https://github.com/76kovka76-hub/sham-vk/settings/secrets/actions.
4. В GitHub Actions Variables добавить `SHAM_BACKEND` = `vedismm`: https://github.com/76kovka76-hub/sham-vk/settings/variables/actions.
5. При очередном запуске SHAM найдёт подключённую группу автоматически через `GET /accounts` по ID `243230846`. Если сервис не возвращает ожидаемый идентификатор, можно дополнительно задать переменную `VEDISMM_ACCOUNT_ID` (внутренний ID аккаунта внутри ВедиSMM, **не** номер VK-группы).

Далее GitHub Actions каждые 15 минут генерирует картинку, отправляет её в медиатеку ВедиSMM и создаёт пост с изображением. Бот проверяет отдельное задание публикации; только успех конкретной VK-цели считается подтверждённым размещением. Если через ~100 секунд статус всё ещё pending, запись фиксируется как **queued**, а не как опубликованная. Статусы и лимиты VK могут меняться. Начните с одного тестового запуска `Run workflow → publish` после настройки и проверьте вид поста в ВК.

При неудачной загрузке изображения текст отдельно не публикуется. Остановить публикацию: `SHAM_PAUSED=true`. Не включайте оба канала сразу: `SHAM_BACKEND` выбирает только один из них.

Источник по возможностям и API: https://vedismm.ru/docs/api

## Редакторский фильтр качества v2 (13 ноября 2026)

- `quality_bank.py` — **30 специально выверенных жизненных тем** (работа, деньги, телефон, дом, общение, повседневность), **600 согласованных сочетаний** коротких завязок и концовок; комбинации из разных тем полностью запрещены. Банк конечен: его необходимо пополнять свежими сценариями; количество постов в сутки не гарантировано.
- `quality_guard.py` блокирует нетематические сочетания, дословные и близкие повторы начальной фразы (90 последних записей), повтор темы в 10 последних записях, и повтор сцены в двух последних постах. Прежняя база случайных шуток больше не подключена.
- Каждому сюжету назначена конкретная визуальная сцена и соответствующая эмоция для AI Horde. На картинке изображается ситуация, соответствующая тексту, а не случайный предмет из общей темы.
- У каждого нового мема в истории `quality_version: 2`, а ошибочные старые записи не используются повторно. При исчерпании подходящих шуток бот **пропускает слот**, а не публикует бессмысленный текст.
- По итогам первой очистки запись ВедиSMM №4967 (старый генератор) успешно снята с расписания; уже вышедшие публикации не удаляются автоматически.
- Для снятия старых сохранённых постов до выхода используйте GitHub Actions → `Run workflow` → `clean-queue`. Команда вызывает VediSMM `POST /posts/{id}/unschedule` **только для старых записей в статусе scheduled** с проверкой актуальной версии; уже опубликованные записи автоматически не удаляются.

## Короткий юмор и смешные сценки для SHAM

- Источники вдохновения: общие мотивы коротких анекдотов, современных интернет-приколов и бытовых наблюдений. Текст адаптируется и пишется заново: не копируем чужие анекдоты, фотографии и готовые мемы слово в слово.
- `short_jokes.py` содержит 18 коротких самостоятельных шуток, а `hard_jokes.py` добавляет 24 новых жёстких, матерных и абсурдных истории. Генератор старается чаще использовать эти цельные истории, затем — согласованный тематический банк.
- `visual_gags.py` задаёт физическое комическое действие для каждой темы вместо случайного красивого лица. `style_catalog.py` содержит 31 жанр: 21 фотографический и фотомонтажный, а также 3D, коллажи, живопись, графику и редкое аниме.
- `sham_free_image.py` использует бесплатный анонимный OVHcloud SDXL, а при его отказе возможен бесплатный AI Horde. Ни платных ключей, ни Openverse, ни скачивания случайных чужих фотографий.
- Наличие коротких сюжетов не отменяет проверку качества и защиту от повторов.

## Исправление низкой частоты SHAM (13 ноября 2026)

- **План**: 4 поста в час (каждые 15 минут), 96 слотов в сутки. **Фактическое число может быть меньше** из-за best-effort GitHub cron, очередей AI Horde и отказов ВедиSMM.
- GitHub Actions иногда запускает плановый workflow только примерно раз в 30 минут, даже при расписании «каждые пять минут». Раньше **один запуск заполнял лишь один 15-минутный слот**, поэтому посты появлялись примерно раз в час.
- Теперь `queue_batch.py` за один запуск пополняет **до 7 отдельных 15-минутных слотов**, пока хватит времени и доступен бесплатный генератор. Отложенная публикация остаётся на стороне ВедиSMM.
- В отличие от старой версии, GitHub Actions сохраняет уже запланированные посты в `state/history.json` **даже если последующая генерация из пакета завершилась ошибкой**. Повторы слотов не допускаются.
- Ограничение полного batch-run — до 39 минут; часть пакета может не успеть. **Запланированный слот** не равен **подтверждённому VK-посту**.
- Исправление проверяется автоматическими тестами на уникальность слотов и сохранение прогресса.

## Буфер отложенных публикаций (автоматическое пополнение)

- Бот пытается поддерживать **12 часов будущих постов** в календаре ВедиSMM.
- GitHub Actions запускается **каждые 5 минут**; если есть свободное место в ближайших 12 часах, создаёт один новый AI-мем и ставит его **в ВедиSMM на ближайший свободный 15-минутный слот**. Первый слот берётся не раньше чем через 30 минут, чтобы успеть завершить нейрогенерацию.
- Запланированная запись не считается опубликованной до фактического выхода. ВедиSMM выпускает её по своему календарю независимо от GitHub и выключенного ПК. Пропуски GitHub продолжительностью менее размера оставшегося буфера не должны нарушать уже созданное расписание.
- В истории `state/history.json` записываются время, внутренний ID записи ВедиSMM и выбранный стиль (один из 31 визуального жанра на каждый слот). Уже занятые слоты не перезаписываются.
- **Не гарантия 96 публикаций:** бесплатный AI Horde, GitHub и ВедиSMM могут быть недоступны; важна проверка фактического статуса постов после выхода. Некоторые задачи могут пропускаться без низкокачественных замен.
- Чтобы поставить один пост в очередь вручную: GitHub Actions → `Run workflow` → режим `enqueue`. Предпросмотр: `preview`. Немедленная отправка: `publish`.

## Стили SHAM: 31 жанр вместо 92 аниме

- `style_catalog.py` вращает 31 жанр изображений между 15-минутными слотами. Соседние слоты имеют разные стили, а аниме встречается лишь несколько раз в сутки.
- 21 жанр опирается на фотографическую реальность: случайные снимки, документальные и киношные кадры, чёрно-белые фотографии, VHS, фотомонтаж и сюрреалистические фотографии. Оставшиеся жанры — 3D, тактильные материалы, художественные рисунки, пиксель-арт и редкое аниме.
- `horde_style.py` и `sham_free_image.py` передают генератору `post["visual"]` и дополнительные физические действия из `visual_gags.py`. Если сюжет строится вокруг предмета или животного, генератору запрещено добавлять посторонний портрет человека.
- Текст шутки рисуется отдельно Python/Pillow поверх изображения, а не поручается нейросети, которая часто ошибается в русских буквах.
- Новый банк `hard_jokes.py` содержит 24 жёсткие самостоятельные шутки. Отбор проверяет последние 18 тем и 60 концовок, а также точные дубли истории.
- У новой версии **нет онлайн-проверки смыслового совпадения нейроизображения и шутки**. Сценарная привязка существенно улучшена, но гарантия идеального совпадения потребует внешней визуальной экспертизы.
- Ранее запланированные в ВедиSMM посты **не изменяются задним числом**. Все новые записи создаются с обновлёнными стилями. Нельзя считать планируемые слоты фактически опубликованными до подтверждения ВК.
- Для работы не требуется TinyFish или платный API; используется прежняя схема GitHub Actions → OVH/AI Horde → ВедиSMM → VK. Пропуски при недоступном бесплатном генераторе возможны.

## Настройка доступа ВК

Для прямого способа VK (SHAM_BACKEND=vk) секреты задаются здесь: https://github.com/76kovka76-hub/sham-vk/settings/secrets/actions

Добавьте в **Repository secrets**:

- `VK_USER_TOKEN` — токен администратора для `photos.getWallUploadServer` и `photos.saveWallPhoto` с подходящими разрешениями.
- `VK_GROUP_TOKEN` — токен сообщества для `wall.post` (можно не задавать: тогда бот попробует использовать пользовательский токен).

**Никакие токены не присылайте в переписку и не записывайте в репозиторий.** Наличие секретов нельзя подтвердить чтением из GitHub; их права проверяются только выполнением задания. Права и авторизацию надо получать через официальные средства ВКонтакте.

Настройка переменных: https://github.com/76kovka76-hub/sham-vk/settings/variables/actions

В **Repository variables**:

| Name | Value |
|---|---|
| `SHAM_PAUSED` | `true` — экстренно остановить публикации; `false` или отсутствие — публикации разрешены |

Запуск SHAM разрешён в GitHub Actions по запросу владельца. Устаревшая переменная `PUBLISH_ENABLED` больше не используется в workflow (сам скрипт сохраняет дополнительный внутренний выключатель для локального запуска).

**Не нужен:** `OPENAI_API_KEY`. Переменных для платной генерации в этой версии нет.

## Как проверить без публикации

Откройте https://github.com/76kovka76-hub/sham-vk/actions, выберите workflow «SHAM — пост каждые 15 минут», **Run workflow** → **preview**.

После завершения скачайте артефакт `sham-preview-...` внизу страницы запуска. В нём будут `sham_meme.png` и `preview.json` (картинка, текст, подпись, все 3 хэштега).

Автоматические `push`-проверки кода также используют только безопасный preview.

## Как включить автопостинг

1. Добавить `VK_USER_TOKEN` (и при необходимости `VK_GROUP_TOKEN`) в GitHub Secrets.
2. Проверить **preview** и картинку.
3. В GitHub Actions проверьте автоматический запуск публикации: при первом успешном посте скрипт покажет ссылку на стену ВК.
4. Далее workflow запускается в :08, :23, :38, :53 каждого часа в UTC; часть запросов AI Horde может завершаться без изображения и без публикации.
5. Для ручного запуска можно выбрать **Run workflow → publish**.

Остановка: установите **Repository variable** `SHAM_PAUSED=true` или отключите workflow через GitHub Actions. Рабочий процесс проверяет паузу перед каждой отправкой.

**Риски:** GitHub Actions может задерживать или пропускать scheduled-запуски. В публичных репозиториях без активности 60 дней расписание может автоматически отключиться. ВК может ограничивать активную публикацию из-за flood control. 96 постов в день — **целевая частота, не гарантия**. Не рекомендуется искусственно обходить ограничения ВК. При ошибке API бот не публикует текст вместо картинки.
